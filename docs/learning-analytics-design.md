# 全平台學習紀錄與管理看板設計

## 目標

讓平台管理員掌握全部兒童使用者的刷題進度、每日活躍、正確率、弱點與異常狀況，同時遵守資料最小化原則。後台預設只顯示暱稱與學生編號，不顯示真實姓名、Email、電話或精確出生日期。

## 每次作答紀錄

每次按下「確認答案」後寫入一筆 `question_attempts`：

- 使用者、題目 ID、科目、單元、知識點與難度
- 選擇答案、正確答案、是否答對
- 作答耗時、是否為錯題複習、所屬 10 題回合
- 作答時間與裝置產生的唯一事件 ID，避免離線重送造成重複計數

## 每日指標

`daily_learning_stats` 依使用者與日期彙總：

- 題數、答對題數、正確率、有效學習分鐘
- 完成回合數、不同題目數、錯題複習數
- 五科題量與正確率、最弱知識點、連續學習天數
- 最後活動時間與資料更新時間

## 後台資訊架構

1. 平台總覽：總學生數、今日活躍、今日題量、平均正確率。
2. 7 日／30 日趨勢：活躍人數、題量、學習時間、留存。
3. 科目健康度：五科正確率、題量與弱點分布。
4. 需要關注：連續未學習、正確率過低、錯題累積、異常快速作答。
5. 學生列表：搜尋、狀態篩選、今日進度、連續天數、弱科與最近活動。
6. 學生詳情：28 日熱度、每日紀錄、科目表現、知識點弱項與最近回合。

## 權限與隱私

- 學生只能新增及查看自己的紀錄。
- 全平台資料只能由 `platform_admin` 角色透過伺服器端 Edge Function 讀取。
- Supabase secret/service key 僅存在 Edge Function，絕不可放在 GitHub Pages。
- 後台需登入、短效 Session、操作稽核、匯出限制與管理員雙因素驗證。
- 未成年人帳號需有監護人同意紀錄、資料保存期限與刪除流程。
- 排名與提醒不得公開羞辱兒童；警示用於協助，而非懲罰。

## 同步策略

PWA 先把事件寫入 IndexedDB outbox，再批次同步。每筆事件使用 UUID 作為冪等鍵；網路中斷時保留在裝置，成功後才移除。伺服器依事件 ID 拒絕重複寫入，並以伺服器時間校正每日統計。

## 上線步驟

1. 建立 Supabase 專案並執行 `supabase/migrations/001_learning_analytics.sql`。
2. 建立學生登入／匿名升級流程與監護人同意頁。
3. 建立作答事件同步 Edge Function。
4. 建立管理員 JWT 驗證與聚合查詢 Edge Function。
5. 將 `admin/` 原型接到管理 API，移除示範資料旗標。
6. 執行 RLS、權限、刪除、重送、離線與負載測試後才開放正式資料。
