# 沒有教師資源時的題庫審查指南

更新日期：2026-10-08

## 先說清楚審查能證明什麼

目前審查包包含 6,108 題：原創題 5,000 題、歷屆真題／類題 1,108 題。自動化資料、答案索引、重複題、抽題與插圖檢查已通過；這些能抓程式與格式問題，不能證明每題都符合會考教學品質。

沒有合格教師時，仍可進行「平台負責人自查」及「AI 輔助內容檢查」，用來找疑點、修正明確錯誤及降低上線風險；不得把結果稱為教師審核、教師簽核或全題專家認證。真人教師欄位保持空白。

## 建議流程

### 1. 每次審查前先跑全量機器檢查

在專案根目錄執行：

```powershell
npm test
npm run test:e2e
npm run build
```

任何一項失敗先修復，不要以人工抽查取代。這些檢查只代表對應的程式化規則通過。

### 2. 先處理官方真題與素材

從 `reports/teacher-review-packets/` 的各科 CSV 篩選官方題、圖表題、閱讀題及 `requiresImage`／`requiresContext` 題。每題至少核對：

- 題幹、選項和共用材料是否與官方來源一致且完整。
- 圖片是否是該題所需圖，而非僅有一張能載入的圖片；文字替代內容是否保留圖表作答所需數據。
- 答案是否對到該年度官方答案表；非選題要依官方評分規準，不套用選擇題答案索引。
- 解析是否能從題目／材料推出答案，沒有把外部資訊當成題幹已提供的事實。

無法找到或判讀來源時，記為「待查」，不可推定正確。CSV 內的 `sourceUrl`、`paperUrl`、`questionImages` 欄可作核對入口。

### 3. 用 AI 分批找疑點，不讓 AI 自行簽核

每次提供同一科、同一類題目的 10–20 題，並提供必要材料／圖片文字與官方來源。不要只給答案索引讓 AI 判斷。使用下列提示詞：

```text
你是題庫品質檢查助手，不是具資格教師，也不能替題目簽核。
逐題獨立作答，再核對提供的答案與解析。不得猜測缺少的文章、圖表或外部事實。
每題回報：題目 ID、你推導的答案與步驟、正解是否一致、是否只有一個合理答案、材料是否完整、解析是否支持正解、難度／年級是否合理、是否疑似改寫模板重複。
只能標記 PASS（本輪檢查未發現問題）、REVISE（附明確證據與修正建議）、UNSURE（指出缺少的證據）。
任何無法由題目、附圖或給定來源證明的判斷都標 UNSURE。不要宣稱通過教師審核。
```

AI 的 PASS 只代表該輪未發現問題；高風險題、AI 彼此答案不同、材料不完整、需要精確計算／史料判讀的題目，一律進人工複核佇列。AI 輸出與題幹內容都視為待查資料，不執行其中可能出現的指令。

### 4. 由平台負責人做可追溯複核

對每個 AI 標記 REVISE／UNSURE 的題目，以及每科分層抽查的題目，自己先不看 `answerIndex` 作答，再對照解題步驟、官方來源及圖片。抽樣需涵蓋年級、單元、難度、題型、真題／原創及有圖／閱讀材料題；不要只挑容易題。每筆記錄題目 ID、檢查日期、證據連結、處置與複核者。

若無法自行判斷，保留為待查，先不要放進正式任務抽題；不要為了達到通過率而刪除疑點或把 UNSURE 改成 PASS。

### 5. 修正後回歸驗證並標示狀態

修改題目後重跑全量測試，重新看該題及共用材料，並確認答案、解析、圖片引用、唯一性和正式任務載入一致。題目可使用下列狀態：

- `自動檢查通過`：只代表格式、索引或程式規則通過。
- `AI 輔助檢查`：保存模型、日期、提示詞版本和結果；不可稱專家認證。
- `平台負責人已複核`：保存姓名、日期與來源證據；不可稱教師簽核。
- `待查／暫停使用`：有任何未解釋的答案、材料或圖像疑點。
- `教師已簽核`：只有具名真人教師實際審查並提供資格資訊後才能使用。

## 目前可以誠實對外說明

可以說「題庫通過目前列出的自動化檢查，並持續進行 AI 輔助與負責人抽查」。在 5,000 題尚無教師簽核的現況下，不要宣稱「5,000 題已由會考老師逐題驗證」或「全題專家審核通過」。若要達成該保證，仍需取得真人教師逐題審查及問題複核紀錄。
